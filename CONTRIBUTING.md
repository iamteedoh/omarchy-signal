# Contributing to omarchy-signal

Thanks for helping improve omarchy-signal. This guide covers local setup,
validation, and the pull request process.

## Ways to contribute

- **Report a bug** using the repository's bug report form.
- **Request a feature** using the feature request form.
- **Send a pull request** after opening an issue for non-trivial changes.
- **Report a vulnerability privately** by following [SECURITY.md](SECURITY.md).

## Prerequisites

- Omarchy 4.x (Quattro) for anything that touches the shell plugin
- Python 3.11 or newer (the tests run on 3.12 in CI)
- Node.js 20 or newer (tests for `Model.js`)
- `qrencode` and ImageMagick (used by a few tests)
- gitleaks 8.30.1 or newer

`signal-cli` is **not** needed to run the test suite: the integration tests
drive the bridge with `tests/python/fake_signal_cli.py`.

## Set up from a clean clone

```bash
git clone https://github.com/iamteedoh/omarchy-signal.git
cd omarchy-signal
make test
```

To try a change on your own desktop, `./install.sh --no-bind --no-menu`
copies the checkout into `~/.config/omarchy/plugins/iamteedoh.signal` and
restarts the bridge and the shell. Do not symlink a checkout into the
plugins directory; every save would reload the shell.

Never commit secrets, tokens, phone numbers, message history, your
`signal-cli` data directory, or values specific to your own machine.

## Run the validation suite

Run the same checks that protect `main`:

```bash
make python        # unit + integration tests against the fake signal-cli
make qml           # node tests for Model.js
make bash          # static checks: syntax, systemd unit, manifest, QML hygiene
make qmlcheck      # loads Service.qml in a throwaway Quickshell (needs Omarchy)
make security      # the adversarial subset
gitleaks git . --config .gitleaks.toml --redact --no-banner
```

Anything visual (the terminal client, the popups, the chat window) should be
checked on a real Omarchy desktop before it is called done; `scripts/demo-env.sh`
gives you a bridge with fictional contacts so you never test against your own
account.

## Project layout

- `manifest.json`, `Service.qml`, `BarWidget.qml`, `ConversationView.qml`,
  `Model.js`, `Emoji.js`: the Quickshell plugin (`Emoji.js` is generated by
  `scripts/gen_emoji_js.py`)
- `bin/omarchy-signal`, `lib/omarchy_signal/`: CLI, terminal client and the
  bridge daemon (`bridge.py`, `rpc.py`, `protocol.py`, `store.py`, `sanitize.py`)
- `systemd/`: the user service unit
- `install.sh`, `uninstall.sh`, `scripts/`: installer, post-update hook, demo
  and generator scripts
- `tests/`: Python, node and bash suites
- `docs/`: status notes and the generated `config.example.toml`
- `.github/workflows/`: validation and source-only release automation

## Pull request process

1. Create a branch from `main`.
2. Make the smallest complete change and update documentation.
3. Run the full validation suite above.
4. Use a [Conventional Commit](https://www.conventionalcommits.org/) PR title:
   `feat:`, `fix:`, `docs:`, `refactor:`, `ci:`, `test:`, or `chore:`.
5. Complete the pull request template and link the related public issue.
6. Wait for all required checks to pass, then squash-merge.

The PR title becomes the squash commit subject and drives release-please:
`fix:` creates a patch release, `feat:` creates a minor release, and a `!` or
`BREAKING CHANGE:` footer creates a breaking release.
